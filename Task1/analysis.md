# Задание 1. Исследование моделей и инфраструктуры

## Анализ задачи

Компания QuantumForge Software нуждается в RAG-боте для обработки ~18 000 документов из различных источников. Решение должно быть:
- **Экономичным** — минимизировать затраты на облачные API
- **Безопасным** — не передавать конфиденциальные данные в облако
- **Масштабируемым** — готовым к растущему объему данных
- **Быстрым** — обеспечить приемлемое время отклика

---

## 1. Сравнение LLM-моделей

### Критерии оценки
- Качество ответов (понимание контекста, точность)
- Скорость работы (latency для time-critical приложений)
- Стоимость владения и использования
- Удобство развёртывания

### Вариант A: Локальные модели (Hugging Face)

**Примеры:** Llama 2 7B/13B, Mistral 7B, OpenAssistant

| Критерий | Оценка |
|----------|--------|
| Качество | 7/10 (хорошо, но уступает коммерческим) |
| Скорость | 8/10 (GPU) / 4/10 (CPU) |
| Стоимость | 2/10 (высокие требования GPU) |
| Развёртывание | 6/10 (требует подготовки инфраструктуры) |

**Преимущества:**
- Полная приватность данных
- Нет лимитов на количество запросов
- Возможность fine-tuning

**Недостатки:**
- Требует GPU (затраты на AWS: ~$1000-2000/месяц)
- Медленнее облачных аналогов
- Требует постоянного обслуживания

### Вариант B: OpenAI GPT-3.5/GPT-4

| Критерий | Оценка |
|----------|--------|
| Качество | 10/10 (лучшее в классе) |
| Скорость | 9/10 (быстрые API) |
| Стоимость | 7/10 (дорого для большого объема) |
| Развёртывание | 9/10 (просто API ключ) |

**Преимущества:**
- Лучшее качество ответов
- Быстрая интеграция
- Нет управления инфраструктурой

**Недостатки:**
- Конфиденциальность — данные передаются OpenAI
- Дорого при большом объеме (для 18K документов + частые запросы = ~$5000+/месяц)
- Зависимость от облачного сервиса

### Вариант C: Yandex YandexGPT (для РФ-ориентированного бизнеса)

| Критерий | Оценка |
|----------|--------|
| Качество | 8/10 (хороший Level, но не лучший) |
| Скорость | 8/10 |
| Стоимость | 6/10 |
| Развёртывание | 8/10 |

**Преимущества:**
- Локализирован для русского языка
- Регуляторная целесообразность
- Дешевле OpenAI

**Недостатки:**
- Менее мощный, чем GPT-4
- Доступен в основном для РФ
- Передача данных в российский облако

### Вариант D: Гибридный подход (локальная модель + облако для сложных запросов)

| Критерий | Оценка |
|----------|--------|
| Качество | 9/10 (лучшее из обоих миров) |
| Скорость | 8/10 |
| Стоимость | 5/10 |
| Развёртывание | 5/10 (сложнее) |

**Преимущества:**
- Простые запросы обрабатываются локально (быстро)
- Сложные запросы идут в облако
- Контроль затрат

**Недостатки:**
- Сложная реализация и обслуживание
- Нужно управлять оба решения

## 2. Сравнение моделей эмбеддингов

### Критерии оценки
- Скорость создания индекса
- Качество поиска (relevance)
- Стоимость владения и использования

### Вариант A: Локальные эмбеддинги (Sentence-Transformers)

**Примеры:** all-MiniLM-L6-v2 (384 dims), bge-base-en (768 dims), multilingual-MiniLM

| Критерий | Оценка |
|----------|--------|
| Скорость индексации | 9/10 (быстро) |
| Качество поиска | 8/10 (хорошо) |
| Стоимость | 1/10 (бесплатно) |

**Преимущества:**
- Полная приватность
- Бесплатно
- Быстрая индексация
- Легко обновлять индекс

**Недостатки:**
- Менее точные, чем OpenAI embeddings
- Требует GPU для быстрой работы

### Вариант B: OpenAI Embeddings (text-embedding-ada-002)

| Критерий | Оценка |
|----------|--------|
| Скорость индексации | 7/10 (зависит от API rate limits) |
| Качество поиска | 10/10 (лучшее) |
| Стоимость | 8/10 ($0.10 per 1M tokens) |

**Преимущества:**
- Лучшее качество поиска
- Оптимизировано для семантического поиска

**Недостатки:**
- Дорого при большом объеме (18K документов + регулярные обновления)
- Конфиденциальность
- Зависимость от API

### Рекомендация для QuantumForge
**Выбор: Локальные Sentence-Transformers (все-MiniLM-L6-v2)**
- Для корпоративной базы знаний, где конфиденциальность критична
- Достаточное качество для внутреннего использования
- Можно индексировать 18K документов за часы без облака
- Стоимость обновления индекса: практически нулевая

## 4. Рекомендуемая конфигурация сервера

### Вариант 1: Минимальный (Development/Testing)
```
CPU: 2-4 cores (t3.medium)
RAM: 4-8 GB
Storage: 50 GB SSD
GPU: нет (не требуется для FAISS + Embeddings)
Стоимость: $30-50/месяц на AWS
```

**Когда подходит:** Прототипирование, тестирование, малые объемы

### Вариант 2: Оптимальный (Production для QuantumForge)
```
CPU: 4-8 cores (t3.large + GPU optional)
RAM: 16-32 GB
Storage: 100 GB SSD
GPU: NVIDIA T4 (если используется локальная LLM)
Стоимость: $200-400/месяц (без GPU) / $600-800 (с GPU)
```

**Конфигурация на AWS:**
- EC2: t3.large (4 vCPU, 8 GB RAM) = $100/месяц
- или c5.2xlarge (8 vCPU, 16 GB RAM) = $300/месяц
- EBS: 100 GB gp3 = $10/месяц
- **Total: $110-310/месяц**

**Облачное решение с OpenAI (дешевле на инфраструктуру):**
- t3.small (1 vCPU, 2 GB RAM) = $30/месяц
- EBS: 50 GB = $5/месяц
- API calls OpenAI: ~$500-1000/месяц
- **Total: $535-1035/месяц**

### Вариант 3: Масштабируемый (Production для растущей компании)
```
CPU: 8-16 cores
RAM: 32-64 GB
Storage: 500 GB SSD + S3 backup
GPU: 2x NVIDIA T4 или A10
Kubernetes для масштабирования
Стоимость: $1000-2000/месяц
```

## 5. ИТОГОВЫЕ РЕКОМЕНДАЦИИ

### Рекомендуемая конфигурация для QuantumForge Software

**Выбранный стек:**
1. **LLM:** Гибридный подход
   - Основной: Mistral 7B (локально, на GPU)
   - Fallback: YandexGPT API (для сложных запросов)
   
2. **Эмбеддинги:** Sentence-Transformers (all-MiniLM-L6-v2)
   - Локальные, быстрые, приватные
   
3. **Векторная БД:** FAISS
   - Максимальная производительность
   - Нулевые затраты на инфраструктуру
   - Простая интеграция с LangChain

4. **Сервер:** AWS EC2 c5.large (с возможностью масштабирования)
   - 4 vCPU, 8 GB RAM базово
   - NVIDIA T4 GPU ($600/месяц дополнительно)
   - EBS: 200 GB SSD
   - **Бюджет: $250-350/месяц**

### Преимущества этого решения:
✅ **Приватность:** Конфиденциальные данные остаются на серверах компании  
✅ **Экономия:** ~$3000-5000/месяц vs облачные решения  
✅ **Масштабируемость:** Можно добавить GPU/памяти без переписи кода  
✅ **Контроль:** Полный контроль над LLM и индексом  
✅ **Скорость:** Low-latency локальные эмбеддинги и поиск  
✅ **Гибкость:** Гибридный подход позволяет балансировать затраты и качество  

### Фазы внедрения:

**Фаза 1 (0-3 месяца): MVP**
- Mistral 7B локально
- FAISS индекс
- Базовый REST API
- ~18K документов
- Сервер: t3.large = $100/месяц

**Фаза 2 (3-6 месяцев): Оптимизация**
- Добавить GPU (T4) для ускорения
- Fine-tune на специфические задачи компании
- Метрики качества и аналитика
- ~$600/месяц

**Фаза 3 (6-12 месяцев): Масштабирование**
- Kubernetes для многих узлов
- Готовность к 500K+ документам
- API для внешних клиентов
- Возможный коммерческий продукт
- ~$2000/месяц

- **Время ответа:** < 2 сек на p95
