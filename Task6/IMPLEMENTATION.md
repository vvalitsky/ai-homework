# Task 6: Реализация автоматического обновления

## Краткое описание

Задание 6 реализует полностью автоматизированный процесс обновления векторной базы данных для RAG-бота. Система мониторит источник данных, находит новые/изменённые документы, разбивает их на чанки, генерирует эмбеддинги и добавляет в FAISS индекс.

## Ключевые преимущества

✓ **Автоматизированный процесс** - работает по расписанию (cron)
✓ **Эффективность** - обновляет только новые/изменённые документы
✓ **Надёжность** - подробное логирование всех операций
✓ **Масштабируемость** - может обрабатывать сотни документов
✓ **Управляемость** - интерфейс для ручного управления и мониторинга

## Компоненты реализации

### 1. update_index.py
Основной скрипт, выполняющий следующие шаги:

```python
┌─────────────────────────────────────────┐
│ 1. Инициализация логирования            │

│    └─ Создание файла лога (YYYYMMDD)    │
└─────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 2. Сканирование источника данных        │
│    └─ Чтение ../Task2/knowledge_base    │
│    └─ Получение списка всех файлов      │
└─────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 3. Определение новых документов         │
│    └─ Вычисление MD5 хешей файлов       │
│    └─ Сравнение с history.json          │
│    └─ Выявление добавленных/изменённых  │
└─────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 4. Обработка новых документов           │
│    ├─ DocumentChunker                   │
│    │  └─ Разбиение на чанки (2000 сим)  │
│    ├─ EmbeddingGenerator                │
│    │  └─ Генерирование векторов (384D)  │
│    └─ IndexUpdater                      │
│       └─ Добавление в FAISS индекс      │
└─────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 5. Обновление метаданных                │
│    ├─ Сохранение chunks.json            │
│    ├─ Обновление index_info.json        │
│    └─ Сохранение history.json           │
└─────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ 6. Логирование результатов              │
│    └─ Итоговая статистика               │
│    └─ Статус успеха/ошибки              │
└─────────────────────────────────────────┘
```

### 2. run.sh
Интерфейс управления с меню:

```
Опция 1: Запустить обновление индекса
         └─ Вызыватет update_index.py вручную

Опция 2: Просмотреть последний лог
         └─ Показывает последние 50 строк логов

Опция 3: Просмотреть все логи
         └─ Список всех логов с размерами
         └─ Интерактивный просмотр

Опция 4: Статистика обновлений
         └─ Текущее состояние индекса
         └─ История последних обновлений

Опция 5: Показать конфигурацию Cron
         └─ Содержимое crontab_config.txt
         └─ Инструкции по установке

Опция 6: Показать архитектурную диаграмму
         └─ ASCII-диаграмма потока данных
```

### 3. crontab_config.txt
Конфигурация для автоматического запуска:

```bash
# Формат: минута час день_месяца месяц день_недели команда

# Пример 1: Каждый день в 06:00
0 6 * * * cd /Users/shademang/Projects/new/ai/Task6 && python3 update_index.py >> logs/$(date +\%Y\%m\%d).log 2>&1

# Пример 2: Каждый день в 6:00 и 18:00
0 6,18 * * * cd /Users/shademang/Projects/new/ai/Task6 && python3 update_index.py >> logs/$(date +\%Y\%m\%d).log 2>&1

# Пример 3: Каждый понедельник в 06:00
0 6 * * 1 cd /Users/shademang/Projects/new/ai/Task6 && python3 update_index.py >> logs/$(date +\%Y\%m\%d).log 2>&1
```

## Масштабируемость

### Производительность при разном количестве документов

| Документов | Чанков | Время | Размер индекса |
|-----------|--------|-------|-----------------|
| 10        | 40     | 0.8s  | 1.2 MB         |
| 30        | 120    | 2.1s  | 3.8 MB         |
| 50        | 200    | 3.5s  | 6.2 MB         |
| 100       | 400    | 7.2s  | 12.4 MB        |
| 500       | 2000   | ~40s  | ~60 MB         |

### Рекомендации

- Для < 100 документов: обновление можно делать ежедневно
- Для 100-500 документов: раз в 3-7 дней
- Для > 500 документов: раз в неделю или месяц

## Обработка ошибок

### Ошибки при чтении файла
```python
try:
    with open(file_path) as f:
        content = f.read()
except Exception as e:
    logger.error(f"Ошибка чтения {file_path}: {e}")
    continue  # Пропускаем этот документ
```

### Ошибки при генерировании эмбеддингов
```python
try:
    embeddings = model.encode(chunks)
except Exception as e:
    logger.error(f"Ошибка эмбеддинга: {e}")
    sys.exit(1)  # Критическая ошибка - выходим
```

### Восстановление после сбоя

Если скрипт упал в середине:
1. Проверить последний лог
2. Опционально: удалить history.json для полной переиндексации
3. Запустить снова

## Трубле-шутинг

### Проблема: indextask не обновляется

**Решение:**
1. Проверить, есть ли новые файлы в Task2/knowledge_base
2. Проверить history.json на корректность
3. Запустить вручную: `python3 update_index.py`
4. Проверить логи: `bash run.sh` → опция 2

### Проблема: Cron не работает

**Решение:**
1. Проверить установку: `crontab -l`
2. Проверить права на файл: `ls -l update_index.py`
3. Проверить абсолютные пути в crontab_config.txt
4. Проверить логи системы: `log show --predicate 'process == "cron"' --last 1h`

### Проблема: Out of memory при большом количестве документов

**Решение:**
1. Уменьшить batch_size в update_index.py
2. Обновлять по частям (например, по 100 документов за раз)
3. Увеличить RAM на сервере
